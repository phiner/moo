# P0.2 Implementation Report — Unified Analysis Context

## 1. Summary
- **Status:** P0.2 implemented (non-live validation passing). Scope limited to unified analysis context/entry, account semantics, traceability/versioning, status separation, IPC compatibility, tests, and docs.
- **DB schema/migrations:** **No database schema changes or migrations**. Traceability fields (`analysis_id`, `rules_version`, requested/context/account, analysis/persistence statuses) are carried in `DecisionOutput.to_dict()` and persisted in existing decision payloads (`recording` stores full output payload/risk JSON) without new tables/columns.
- **Out of scope (not implemented):** P0.3 quote snapshot/quality engine, P0.4 pricing audit fixes, DB/schema redesign, monitor/scanner refactors, TUI rewrite, new strategies, automated/real trading.

## 2. Implemented changes

### 2.1 Unified context and models
- Added `src/mooc/domain/analysis.py`:
  - `AccountContext` (explicit `account_id`, `trd_env`, `currency`, `account_equity`, `available_cash`, `buying_power`; no fabrication/cross-fill).
  - `AnalysisContext` (`analysis_id`, `symbol`, `requested_at` tz-aware, `rules_version`, `account`, snapshot refs placeholders, `entrypoint`).
  - `AnalysisResultStatus` (`OK`, `INSUFFICIENT_DATA`, `RULE_NOT_CONFIGURED`, `INVALID_INPUT`, `CALCULATION_ERROR`, `STALE_DATA`, `PERSISTENCE_ERROR`).
  - `PersistenceStatus` (`saved|skipped|failed|not_attempted`, message) and `AnalysisRunResult`.
  - `new_analysis_id()` (UUID) generated at analysis request/entry.
- Extended `src/mooc/domain/decision.py:DecisionOutput` (additive, backward-compatible defaults): `analysis_id`, `requested_at`, `rules_version`, `analysis_status`, `account`, `context`; all existing keys preserved in `to_dict()`.

### 2.2 Rules versioning (actual loaded rules)
- `src/mooc/services/rules.py`: added deterministic `compute_rules_version(rules, rules_path)` = SHA-256 of canonical JSON over normalized effective rule content (including path and tri-state/UNSET/null distinctions). Version reflects actually loaded rules; load failure yields no fabricated version (`rules_version=None`, explicit error/status).

### 2.3 Unified analysis business entry
- Added `src/mooc/services/analysis.py`:
  - `load_rules_with_version(config)` -> `(rules, rules_version, load_error)`.
  - `resolve_account_context(client, config, account_id/trd_env/currency)` resolves via `policy.resolve_trd_env` + `opend.trade.get_funds` (uses provided client; daemon path uses daemon-owned client). Maps `total_assets -> account_equity`, `cash -> available_cash`, `power -> buying_power` distinctly; missing/unavailable funds return explicit account shell + note (never fabricated).
  - `build_analysis_context(...)` generates `analysis_id` at entry if not provided.
  - `run_analysis(...)` **single business entry**: loads/accepts rules+version, builds context, runs `analyze_symbol` with equity from context only, derives `analysis_status` (e.g. `RULE_NOT_CONFIGURED` on rules load failure; `INSUFFICIENT_DATA` when account requested but unavailable or sizing equity/reasons indicate insufficiency), attaches traceability/context to output, persists (optional) with explicit `PersistenceStatus`, returns `AnalysisRunResult` separating `analysis_status` and `persistence` (analysis result retained even if persistence fails).
  - `persist_analysis(...)` records via existing storage/recording and returns saved/skipped/failed.
  - `analysis_result_to_ipc(...)` maps to protocol response.

### 2.4 Daemon path (IPC) unified
- `src/mooc/services/market_data.py`:
  - Caches loaded rules + computed `rules_version` + load error at init.
  - `_analysis` resolves account context (optional `acc_id/trd_env/currency`) and calls `run_analysis(..., entrypoint="daemon", persist=True)`; returns enriched `AnalysisResult` including `analysis_id`, `analysis_status`, `rules_version`, `requested_at`, `persistence`, `account`, `notes` while keeping `output` as primary payload.
  - Persistence failures no longer hidden: surfaced in `persistence.status/message` and notes (analysis output still returned).

### 2.5 CLI path unified (no separate core calculation)
- `src/mooc/cli.py`:
  - `probe analyze` now loads rules+version and calls `resolve_account_context` + `run_analysis(..., entrypoint="cli", persist=True)` via the same business service; removed direct `analyze_symbol`/manual `record_decision` fork.
  - Added optional `--trd-env`, `--currency` (alongside existing `--acc-id`).
  - JSON output remains additive/backward-compatible (`output` fields preserved) and now includes `analysis_id`, `requested_at`, `rules_version`, `analysis_status`, `persistence`, `account`, `notes` plus compatibility `recorded`/`record_note`.
  - Text output includes `analysis_id`, `analysis_status`, `rules_version`, persistence status/note and notes.

### 2.6 IPC protocol (backward-compatible)
- `src/mooc/ipc/protocol.py`:
  - `GetAnalysis`: added optional `acc_id: int|None (gt=0)`, `trd_env: Literal["SIMULATE","REAL"]|None`, `currency: str|None` (old `{code}` requests remain valid).
  - `AnalysisResult`: kept `output` required; added optional `analysis_id`, `symbol`, `requested_at`, `rules_version`, `analysis_status`, `persistence`, `account`, `notes`.
  - Unrelated IPC messages unchanged.

### 2.7 Behavior for missing/insufficient data
- No fabricated account equity/cash/buying power or contract counts.
- Market/volatility/event/trend analysis still computed when possible; sizing/risk uses only explicit positive `account_equity`.
- When account was requested but unavailable, or sizing cannot be concluded due to missing equity/undetermined risk inputs, `analysis_status` is `INSUFFICIENT_DATA` (with explicit notes/reasons) while analysis output is still returned.
- Rules load failure: `RULE_NOT_CONFIGURED`, `rules_version=None`, no invented version.

## 3. Call path changes (CLI vs Daemon)
| Aspect | Before | After |
|---|---|---|
| Business entry | CLI: direct `analyze_symbol` + local record; Daemon: `MarketDataService._analysis` + direct compute/record | Both use `services.analysis.run_analysis` (same core compute, context, status, persistence semantics) |
| Context | Ad-hoc (CLI optional equity only) | `AnalysisContext`/`AccountContext` with `analysis_id` generated at entry, `requested_at`, `rules_version`, entrypoint, account fields |
| Account resolution | CLI fetched funds locally by `--acc-id`; daemon had none | Optional `acc_id/trd_env/currency` resolved via policy-checked funds lookup using provided client (daemon resolves within daemon-owned client path; CLI resolves via its connected client) into explicit equity/cash/buying_power |
| Rules version | None | Deterministic SHA-256 of actual effective loaded rules |
| Persistence reporting | Daemon swallowed errors; CLI ad-hoc `recorded/record_note` | `persistence` status separated from `analysis_status` in IPC/CLI payloads; failures explicit, analysis preserved |

## 6. Key risks / remaining issues
- **Legacy direct analysis API:** `services.analyze.analyze_symbol` still exists for internal use/tests; core production paths for `probe analyze` and daemon `GetAnalysis` are unified through `services.analysis.run_analysis`.
- **Status granularity:** `analysis_status` derivation is intentionally conservative/minimal for P0.2 (e.g. stale/invalid-input cases not fully classified pending P0.3 data-quality work).
- **Persistence key/idempotency:** recording idempotency remains tied to existing `(symbol,strategy,created_at)` semantics; `analysis_id` is now carried in payload/output for traceability but DB-level unique indexing on `analysis_id` was not added (no migration per scope).
- **Daemon rules cache:** daemon caches rules/version at service init (consistent with prior behavior); runtime rule-file changes require service restart to refresh (same operational model as before, now with explicit version of loaded set).
- **Live verification pending:** OpenD-dependent end-to-end behavior not revalidated in this environment.
- P0.3/P0.4 items remain open as previously documented.
